# Notas de Autoria — Contrato OpenAPI 3.1 (UC-08.06a)

> **Fonte**: `brief-paralelo-2026-10-24-21.md` · **Alvo**: `docs/api/openapi.yaml` · **Decisão**: `D-08`

## 1. Premissas Arquiteturais

1. **Fonte Única de Verdade**:
   O contrato em `docs/api/openapi.yaml` define o contrato HTTP canônico do DevTasks (shelf + shelf_router), eliminando o acoplamento do cliente ao Serverpod.
2. **Envelope de Erro Uniforme**:
   Todas as rotas que falham retornam `application/json` com o schema `Error`:
   ```json
   {
     "errorCode": "ERR_XXX",
     "message": "texto compreensível para o usuário",
     "field": "opcional (ex: email, password, name)"
   }
   ```
3. **Segurança Bearer Global**:
   Todas as rotas são protegidas por padrão via scheme `bearerAuth` (`Authorization: Bearer <token>`). Rotas públicas (`/health`, `/auth/signup`, `/auth/signin`) sobrescrevem explicitamente com `security: []`.

## 2. Rastreabilidade das Invariantes de Negócio

| Invariante | Descrição | Materialização no Contrato |
|:---|:---|:---|
| **INV-01** | Isolamento multi-tenant & anti-enumeração | Rotas escopadas por workspace (`/workspaces/{id}`, `/workspaces/{id}/members`, `/workspaces/{id}/projects`, `/projects/{id}`) retornam `404 ERR_NOT_FOUND` idêntico tanto para recurso inexistente quanto para chamadas de não-membros. |
| **INV-05** | Projeto arquivado = somente leitura | Mutações em projetos (`PATCH /projects/{id}`) rejeitadas se status for `archived`. |
| **INV-06** | Permissão estrita por papel (RBAC) | Mutações de workspace (`PATCH`), membros (`POST/DELETE`) e projetos (`POST/PATCH`) exigem papel `owner`. Papel `developer` ou `viewer` recebe `403 ERR_INSUFFICIENT_ROLE`. |
| **INV-08** | E-mail único e normalizado | `/auth/signup` normaliza espaços e caixa (`trim` + `lowercase`). Duplicatas retornam `409 ERR_EMAIL_ALREADY_TAKEN`. |
| **INV-09** | Membresia única por workspace | Adição de membro já existente (`POST /workspaces/{id}/members`) retorna `409 ERR_MEMBER_ALREADY_EXISTS`. |
| **INV-SEC-04** | Anti-enumeração de identidade no login | `/auth/signin` responde com `401 ERR_INVALID_CREDENTIALS` tanto para senha incorreta quanto para e-mail não cadastrado. |
| **INV-SEC-13** | Proteção contra DoS e computação de hash | Rate limiting de 10 tentativas / 60s atua na fronteira, retornando `429 ERR_RATE_LIMITED` antes de qualquer verificação de hash. |
| **INV-SEC-16** | Credenciais via header-only | Tokens trafegam exclusivamente via `Authorization: Bearer <token>`. Endpoints privados (`/auth/signout`, `/me`, etc.) não aceitam tokens no corpo nem na URL. |
| **INV-SEC-17** | Token opaco | Sessão emite token opaco aleatório de 32 bytes (CSPRNG, `INV-SEC-10`). |

## 3. Inventário Completo de Rotas (15 endpoints)

1. `GET /health` — Verificação de prontidão e saúde do processo (público).
2. `POST /auth/signup` — Cadastro de usuário (público; 201 `{userId}`).
3. `POST /auth/signin` — Login (público; 200 `{sessionToken, userId}`).
4. `POST /auth/signout` — Encerramento de sessão (🔒; 200 `{}`).
5. `GET /me` — Perfil do usuário autenticado (🔒; 200 `{userId, name, email}`).
6. `POST /workspaces` — Criação de workspace (🔒; 201 `{workspace}`).
7. `GET /workspaces` — Listagem de workspaces do usuário (🔒; 200 `{workspaces: [...]}`).
8. `GET /workspaces/{id}` — Detalhes de um workspace (🔒; 200 `{workspace}`).
9. `PATCH /workspaces/{id}` — Renomeação de workspace (🔒, owner; 200 `{workspace}`).
10. `POST /workspaces/{id}/members` — Adição de membro (🔒, owner; 201 `{workspace}`).
11. `DELETE /workspaces/{id}/members/{userId}` — Remoção de membro (🔒, owner; 200 `{}`).
12. `POST /workspaces/{id}/projects` — Criação de projeto (🔒, owner; 201 `{project}`).
13. `GET /workspaces/{id}/projects` — Listagem de projetos ativos (🔒; 200 `{projects: [...]}`).
14. `PATCH /projects/{id}` — Renomeação de projeto (🔒, owner; 200 `{project}`).
15. `POST /projects/{id}/archive` — Arquivamento idempotente de projeto e regra somente-leitura (🔒, owner; 200 `{project}`; INV-05).
